# Retrieval evaluation — 2026-08-21

Criterion 3 of `docs/02-thesis.md`: recall@5 ≥ 0.85.

## Setup

- 34 chunks from 6 documents, cut on heading boundaries
- 30 hand-written queries, each mapped to the document that must be retrieved
- The golden set was written by **reading the content**, not by running the
  retriever. Writing questions from retriever output measures the retriever
  against itself and always scores well.

## Results, k = 5

| Config | Backend | recall@5 | MRR |
|---|---|---|---|
| Lexical only | BM25 | 0.933 | 0.729 |
| **Hybrid** | BM25 + local trigram, RRF k=60 | **0.967** | **0.831** |

Both clear the 0.85 threshold. Hybrid adds **+0.034 recall** and **+0.102 MRR** —
the MRR gain is the more meaningful one: relevant documents surface higher, which
matters because the chat sends only the top few chunks to the model.

## Honest caveat on the backend

The vector leg here is a **hashed-trigram stand-in**, not a semantic embedding
model. It exists so fusion, budgeting and degradation logic can be tested
deterministically with no network and no credentials, and so CI runs the same code
path production runs.

**These numbers must not be reported as embedding-model performance.** The harness
prints that warning on every run, and the config column names the backend so a
number can never be quoted without it.

When Upstash Vector is provisioned, the same harness runs against real embeddings
and this table gets a third row. The comparison is the point: if real embeddings do
not beat 0.967, that is a publishable finding about small-corpus retrieval — a
25-document corpus may simply not need a vector leg, and pretending otherwise would
be adding infrastructure for its own sake.

## The one miss

`"what happens when two compactions run at once"` — the answer is in the
context-compaction document (advisory lock, loser declines) but the query's
vocabulary does not overlap the prose, which says "concurrent attempts" rather than
"at once". A real embedding model should close this gap; that is a concrete,
falsifiable prediction to test once it is wired.

## Reproduce

```bash
tsx bench/retrieval/eval.ts --k 5        # exits non-zero below threshold
tsx bench/retrieval/eval.ts --k 5 --json # also writes results/latest.json
```
