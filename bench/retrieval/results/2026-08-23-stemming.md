# Stemming vs synonym expansion — 2026-08-23

Closes the trigsight deepening track: *"one retrieval query still misses at recall 0.967, and query
expansion is untested."*

## The miss

`what happens when two compactions run at once` — the only query the golden set could not answer at
k=5. Recall sat at 0.976 across 42 queries.

The document that answers it, `work/context-compaction`, says:

> A transaction-scoped advisory lock serialises concurrent attempts, and the loser declines rather
> than queueing.

Term-by-term against the query:

| query term | in the document |
|---|---|
| `compactions` | **no** — the document says `compaction` |
| `happens` | no |
| `once` | **no** — the document says `concurrent` |
| `what`, `when`, `two`, `run` | yes, and each is near-worthless for ranking |

So BM25 contributed nothing: the single most distinctive term in the query differed from the
document's by one letter. The answer surfaced at **rank 6** on the vector leg alone — retrieved, one
place below the cutoff.

That is worth stating precisely, because "retrieval missed it" and "ranking put it sixth" call for
different fixes, and only the second was true.

## Two candidates, measured

Both were implemented as throwaway probes under `bench/retrieval/exp/`, changing nothing in `src/`.

| config | recall@5 (42 queries) |
|---|---|
| baseline, as shipped | 0.976 (41/42) |
| stemming only | **1.000** (42/42) |
| synonym expansion only | **1.000** (42/42) |
| stemming + expansion | 1.000 (42/42) |

*Measured by reverting `src/lib/retrieval/bm25.ts` and running `bench/retrieval/eval.ts`, not by the
probes' own "baseline" row. The probes build their own lexical index but take the vector leg and
`chunk.searchText` from `src/`, so once stemming shipped their baseline row was partly measuring the
fix — it printed 1.000 for a configuration that really scores 0.976. See `exp/README.md`.*

**The golden set could not distinguish them.** Both fixes reach 1.000, so measuring against the set
the fix was written for says nothing about which is better — the classic way to talk yourself into
tuning to the test.

## The held-out set, which could distinguish them

Eight queries written *after* the candidates existed, never used to tune anything, each a plural or
tense variant of a term the corpus states in another form:

| config | held-out |
|---|---|
| baseline | 6/8 |
| stemming | **7/8** |

*Same method: real code reverted, real eval. An intermediate re-run appeared to show 7/8 for both
configurations, which would have withdrawn the entire basis for this decision. It was an artifact of
the two problems above — the probe measuring the shipped index, and `content/projects/trigsight.mdx`
having been added to the corpus between runs, which changes the IDF of every term at 71 chunks. The
figures here are from a clean revert.*

Stemming generalises to queries it was not built for. A synonym list cannot, by construction: it
only helps vocabulary someone anticipated, and the entry that fixed this query (`once` →
`concurrent`) was written by reading the document that was missing. That is tuning to the test with
extra steps.

**Decision: stemming. Expansion declined.**

## What shipped

`tokenise` now stems, with a four-character minimum stem so identifiers survive.

Deliberately **not** a Porter stemmer, and deliberately conservative. Aggressive stripping is worse
than none in technical prose: `axes` must not become `ax`, `cache` must not become `cach`. The length
guard is what protects them. `ies → y` rather than truncation, so `policies` becomes `policy` rather
than `polic` — a stem matching no real word matches no document either.

| | recall@5 | MRR |
|---|---|---|
| lexical only, before | 0.929 | 0.806 |
| lexical only, after | **0.952** | 0.841 |
| hybrid, before | 0.976 | 0.905 |
| hybrid, after | **1.000** | 0.913 |

The lexical leg gained more than the hybrid did, which follows: stemming fixes a vocabulary mismatch,
and the vector leg was never the thing failing.

## A second bug this exposed

`tokenise` is also used by the MCP server's relevance floor, which required a query term to appear in
a chunk before reporting it as evidence. With stemming, that compared **stemmed query terms against
raw chunk text**.

It worked, and only by accident: a stem is usually a prefix of the word it came from, so a substring
test finds it. The accident ends at any suffix rule that is not plain truncation — `policies` stems
to `policy`, which appears nowhere in a document that says "policies", and the floor would have
silently rejected real evidence.

Both sides are now tokenised, and the comparison is between token sets rather than substrings, which
also removes a pre-existing accident: a term matching inside an unrelated word.

Verified in both directions afterwards — four claims this corpus genuinely documents are supported,
and `quantum cryptography ion traps` is still refused.

## What this does not fix

`which rules cite clauses` still misses, in both configurations. The corpus says each rule "carries
the clause it enforces"; the query says "cite". That is a genuine paraphrase gap, not a morphological
one, and stemming cannot reach it. Left open and stated rather than patched with the synonym list
this result just declined.

## Three rules were tried and removed, each for a measured reason

The shipped stemmer strips `-s` and `-es`, rewrites `-ies → y`, and does nothing else. It did not
start there.

| rule | why it went |
|---|---|
| `-ation` | Broke idempotence in the worst direction: `reservations → reservation` (strip `s`) while `reservation → reserv` (strip `ation`). A rule added to merge plural and singular drove them apart. |
| `-ing` | Measured and earned nothing — golden 42/42 and held-out 7/8 with it and without. It cost `ceiling → ceil`, `embedding → embedd`, `heading → head`. Paying with correctness for no gain. |
| longest-suffix-first ordering | The original order over-stripped. Shortest-first fixes it, but then `-ies` must be checked *ahead* of `s`, because it rewrites rather than truncates: otherwise `policies → policie`, a word in no language, matching nothing. |

Also: any word ending `-ss` is left alone. `across → acros`, `access → acces`, `useless → useles` —
eighteen corpus terms. Harmless for matching, since query and document are mangled identically, but
it made `stem` non-idempotent, and a function whose output is not a fixed point cannot be applied to
an already-stemmed index.

**None of these were caught by recall**, which had already reached 1.000. They were caught by
stemming the entire corpus vocabulary and re-stemming the result — 1,432 terms, 0 unstable. That
check is now a test.
